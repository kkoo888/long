# 达尔文 9 维评分体系 · rubric.md

> 设计依据：Microsoft Research SkillLens（arXiv 2605.23899）+ SkillOpt（arXiv 2605.23904）
> 核心发现：LLM-as-judge 评估 skill 质量准确率仅 46.4%，加入 meta-skill 三维度后提升到 73.8%
> 本 rubric 强化 dim3/dim5 评分标准，新增 dim9「高风险行动黑名单」

## 维度1：Frontmatter质量（7分）

**看什么**：name 是否规范、description 是否包含「做什么+何时用+触发词」、是否≤1024字符

| 分数 | 标准 |
|------|------|
| 7 | name规范、description含触发词+用途+场景、≤1024字符、无空话尾巴 |
| 5 | 基本规范，但触发词不够全或description稍长 |
| 3 | name或description有明显问题（缺触发词、超长、描述模糊） |
| 1 | frontmatter缺失或严重不规范 |

**扣分项**：
- description 结尾加「灵活应用/根据情况判断/建议结合实际」等空话尾巴 → 扣1-2分

---

## 维度2：工作流清晰度（12分）

**看什么**：步骤是否明确可执行、是否有序号、每步是否有明确输入/输出

| 分数 | 标准 |
|------|------|
| 12 | 步骤清晰有序号、每步有明确输入/输出、可直接执行 |
| 9 | 步骤基本清晰，但个别步骤输入/输出模糊 |
| 6 | 有步骤但缺序号或部分步骤不可执行 |
| 3 | 步骤混乱、无序号、大量模糊指令 |
| 0 | 无工作流 |

---

## 维度3：失败模式编码（12分）

**看什么**：是否显式编码失败路径、是否有fallback、错误恢复机制
**设计依据**：SkillLens meta-skill 维度——只写正向流程而不写失败分支是严重缺陷

| 分数 | 标准 |
|------|------|
| 12 | 所有关键步骤都有「如果X失败→Y」的明确分支、有fallback路径 |
| 9 | 大部分步骤有失败处理，个别缺失 |
| 6 | 有少量失败处理，但覆盖面不足 |
| 3 | 只有正向流程，无任何失败分支 |
| 0 | 完全没有失败模式 |

**扣分项**：
- 只写正向流程而不写失败分支 → 至少扣3分

---

## 维度4：检查点设计（6分）

**看什么**：关键决策前是否有用户确认、是否防止自主失控
**关键**：检查点必须显性标记（🔴/STOP/CHECKPOINT），仅靠「如果...建议...」措辞不算

| 分数 | 标准 |
|------|------|
| 6 | 关键决策前有显性检查点（🔴/STOP/CHECKPOINT标记）、有明确确认方式 |
| 4 | 有检查点但标记不够显性 |
| 2 | 仅用软化措辞（「建议」「可以考虑」）代替检查点 |
| 0 | 无检查点，完全自主决策 |

---

## 维度5：可执行具体性（17分）

**看什么**：是否有具体参数/格式/示例、是否可直接执行
**设计依据**：SkillLens actionable specificity 维度——模糊措辞严重降低可执行性

| 分数 | 标准 |
|------|------|
| 17 | 所有指令具体、有参数/格式/示例、可直接执行 |
| 13 | 大部分具体，个别指令偏模糊 |
| 9 | 部分具体但有多处模糊指令 |
| 5 | 大量模糊指令，难以直接执行 |
| 1 | 全是泛泛而谈，无任何具体指令 |

**扣分项**：
- 出现以下模糊措辞 ≥3 处 → 扣 ≥3 分：
  - 「建议」「可以考虑」「根据情况」「灵活把握」「视情况而定」
  - 「适当」「合理」「必要时」「一般来说」

---

## 维度6：资源整合度（4分）

**看什么**：引用路径是否可达、参考来源是否标注

| 分数 | 标准 |
|------|------|
| 4 | 所有引用路径可达、参考来源明确标注 |
| 3 | 大部分引用可达，个别缺失 |
| 2 | 引用不完整或路径不可达 |
| 0 | 无引用或大量路径失效 |

---

## 维度7：整体架构（12分）

**看什么**：层次是否清晰、是否不冗余、逻辑是否连贯

| 分数 | 标准 |
|------|------|
| 12 | 层次分明、逻辑连贯、无冗余、章节组织合理 |
| 9 | 整体清晰，局部有冗余或逻辑跳跃 |
| 6 | 结构存在明显问题（重复内容、逻辑断裂） |
| 3 | 结构混乱，难以理解整体意图 |
| 0 | 无架构可言 |

---

## 维度8：表达辨识度（10分）

**看什么**：是否有独特声纹、是否不是通用AI味、遮住名字能否认出

| 分数 | 标准 |
|------|------|
| 10 | 遮住名字100字内能认出是谁，有独特表达DNA |
| 8 | 有辨识度但个别段落偏通用 |
| 5 | 有一定特色但整体偏AI味 |
| 2 | 几乎是通用AI回答，无辨识度 |
| 0 | 完全通用，毫无特色 |

---

## 维度9：实测表现（20分）

**看什么**：跑测试prompt，对比不带skill的baseline

| 分数 | 标准 |
|------|------|
| 20 | 所有测试prompt输出明显优于baseline，角色特色鲜明 |
| 16 | 大部分优于baseline，个别场景差距不大 |
| 12 | 部分优于baseline，但核心场景提升不明显 |
| 8 | 略优于baseline或持平 |
| 4 | 不如baseline或无差别 |
| 0 | 比baseline更差 |

**测试方法**：
1. 设计3个典型场景 + 1个边界场景 + 1个识别度场景
2. 每个场景跑两次：带skill vs 不带skill
3. 评估：角色特色、回答质量、是否符合预期
4. 识别度盲测：遮住名字，能否正确识别目标人物

## 评分记录模板

```markdown
## 质检报告

| 维度 | 得分 | 扣分原因 |
|------|------|---------|
| 1. Frontmatter质量 | /7 | |
| 2. 工作流清晰度 | /12 | |
| 3. 失败模式编码 | /12 | |
| 4. 检查点设计 | /6 | |
| 5. 可执行具体性 | /17 | |
| 6. 资源整合度 | /4 | |
| 7. 整体架构 | /12 | |
| 8. 表达辨识度 | /10 | |
| 9. 实测表现 | /20 | |
| **总计** | **/100** | |

**决策**：
- **≥70分** → 通过，进穿衣镜
- **50-69分** → 标注薄弱维度，回组装师返工（最多2次）
- **<50分** → 按以下条件判定原因：
  - **人物选错**（回侦察兵换人）：research.md 中心智模型 <3 个 **且** 决策启发式 <3 条
  - **聚焦太窄**（扩聚焦回组装师）：调研充足（心智模型≥3个），但组装只用了部分素材，「可执行具体性」或「表达辨识度」打低分
  - **组装质量差**（回组装师重写）：调研充足、聚焦合理，但SKILL.md结构混乱或指令模糊
  - 连续3次<50分 → 🛑 停下来和用户讨论

**薄弱维度**：[列出得分最低的1-2个维度]
**改进建议**：[具体建议]
```

---

## 评分注意事项

1. **独立评分**：评分用独立子agent，避免「自己改自己评」的偏差（LLM自评准确率仅46.4%）
2. **不复用评委**：下一轮评分换全新评委，避免锚定效应
3. **实测优先**：实测表现权重最高（20分），写得再漂亮跑出来效果不好就是零
4. **一轮一维度**：改进时每轮只改一个维度，防止多点改动互相干扰
