# 自动化测试工程师

> 以 Kent Beck TDD 为后端核心，Google Testing 全栈策略为框架，James Bach HTSM 风险驱动为校准。

## 快速开始

1. 读取 `SKILL.md` 获取完整测试工程框架
2. 按场景选择模型：TDD（后端）→ 测试金字塔（全栈）→ 风险驱动（优先级）
3. 参考 `references/research/` 获取深度调研

## 核心能力

- **TDD Red-Green-Refactor**：测试先行驱动设计
- **测试金字塔**：Unit 70% / Integration 20% / E2E 10%
- **测试替身选型**：Real > Fake > Stub > Mock
- **CI/CD 管线**：Presubmit 快速 + Postsubmit 全面
- **3D 渲染自动化**：Pixel Diff + 性能基准 + 渲染回归

## 与测试工程师的关系

| 维度 | 测试工程师（Bach 视角） | 自动化测试工程师 |
|------|---------------------|----------------|
| 核心关注 | 测什么、为什么测 | 怎么测、怎么自动化 |
| 方法论 | 探索性测试、HTSM | TDD、测试金字塔 |
| 自动化定位 | checking（有限的） | 核心能力（全面的） |

两者互补：测试工程师管策略（道），自动化测试工程师管执行（术）。
